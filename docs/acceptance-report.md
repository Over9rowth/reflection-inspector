## R01 · 镜子与玻璃分别评估，报告漏检/误检与资源占用

**判定：部分验证（未达验收）**

- 已有 `docs/model-evaluation.md`：开发集 7 张（mirror 3 / glass 3 / none 1），逐样本类别级观察，来源与许可见 `tests/fixtures/sources-eval.json`。
- **该文档自己写明了三处不足**，本轮不推翻也不粉饰：
  1. 无人工逐框真值（GT），因此**没有任何命中率/精确率/召回率数字**，只有定性观察；
  2. 样本同时用于观察与调参，**不能当作验收集**；冻结集尚未建立；
  3. 负样本只有 1 张（n=1），不足以估计误检率。
- 资源占用：`docs/mirror-run.log` / `docs/glass-run.log` / `docs/threshold-scan.log` 记录了逐样本耗时与显存峰值，但**本轮未重跑**，数字沿用 2026-10-28 记录。
- 结论：**R01 不能判通过**。要判通过，需要先建冻结集（不与调参共用）并做 GT 标注。

## R03 · 手动补选屏幕/金属；EXIF 8 方向、不同缩放/镜像、非整数比例映射后边界与原图一致

**判定：部分验证**

- 手动补选：桌面冒烟里除 3 条自动建议外，额外加了一条**手动区域**并成功进入导出（`docs/smoke-0.2.0.log`，覆盖 1,916,597 像素）。
- 缩放不造成偏移：画布坐标 → 原图坐标的映射在 `src/renderer/main.tsx` 里按 `scale` 反算，冒烟导出尺寸与预览一致（4016×6016）。
- **未验证**：EXIF 8 方向的边界一致性、镜像视图下的框选、非整数缩放比例下的 1px 级偏差。本轮没有构造这几种夹具。

## R04 · 翻转/提亮后导出完整照片；未经编辑的观察变换不进入成品；选区边框不进入成品

**判定：已实测通过（导出侧）**

- 导出走的是「原图解码 → 掩码/矩形绘制 → 重编码」，**不是截屏**，因此观察用的缩放、平移、提亮天然不进入成品。
- 冒烟实测：原图 4016×6016，导出 4016×6016，30,633,682 字节（PNG）。
- 纯手动路径实测：原图 4016×6016，导出 4016×6016，26,634,837 字节，回读尺寸一致。
- 选区边框由 UI 叠加层绘制，不参与导出绘制。

## R05 · 原分辨率填充/马赛克、撤销重做、重叠编辑与透明图一致；实心填充须通过替换输入不变性检查

**判定：部分验证**

- 原分辨率填充与马赛克：`src/domain/paint.mjs`（BGRA 原地绘制），`tests/paint.test.cjs` 7 项覆盖矩形归一化、`expand` 越界裁剪、块内均值、边缘残块、`cover` 嵌套与非法编辑。
- 重叠编辑：`applyEdits` 按数组顺序叠加，后一条覆盖前一条；单测覆盖「2 条编辑 + 1 条空矩形 + 1 条 null」的计数。
- 透明图：**未验证**。`fillRect` 保留 alpha 字节，但没有用真实带透明通道的 PNG 实测。
- 撤销/重做：界面层状态操作，**本轮未做自动化验证**。

## R06 · 保存重开、源文件移动/替换、只读目标、磁盘满、worker 崩溃均正确恢复

**判定：部分验证**

- 保存重开：`npm run smoke:manual` 导出后立即用本地解码回读，尺寸与原图一致（4016×6016）。
- worker 崩溃：主进程 `child.on('exit')` 会把在途请求全部 reject，界面显示「推理进程不可用」横幅；**并且**此时导出会自动退回本地绘制（`export:run` 的 catch 分支），手动模式不受影响。
- **未验证**：源文件在会话中被移动/替换、只读目标目录、磁盘满。这三项需要专门构造故障，本轮未做。
